# 00 · 地基复盘与修正（必读）

> 版本：v7.0 | 2026-07-29
> **地位**：高于其他所有文档。若与其它文档冲突，以本文为准。

---

## 为什么要写这篇

前面 v6 文档把功能列全了，但**有几处地基决策会埋雷**。大项目一旦选错：

- 多子域名登录共享 → 后期改不动
- 钱包多币种没想清楚 → 账对不平
- HLS 只在 API 鉴权 → 付费内容被盗链
- 4 周承诺过重 → 团队赶工期、地基偷工

本文只做一件事：**把会返工的地基错误揪出来，给出修正后的正确决策**。

## 一、已发现的地基级问题（按严重程度）

### ❌ 问题 1：4 周做完 24 项 + 多支付 = 不现实（预期管理错误）

**原方案**：4 周 MVP 上线，24 项功能全做。

**问题**：
- 原 PDF 是 **12 周**，这更接近真实
- 上传转码 + 支付多渠道 + KYC + 分账 + 双语，任一项都可能卡 3–5 天
- 赶工期时最先牺牲的是：事务一致性、对账、签名 URL、压测——恰恰是地基

**修正**：

| 阶段 | 时间 | 目标 |
|---|---|---|
| **地基期 Foundation** | W1–2 | 工程骨架、双语、DB、鉴权、支付抽象、对账骨架、HLS 签名 |
| **闭环期 Closed Loop** | W3–6 | 上传→播放→充值→解锁→分账→提现 **一条真链路** |
| **运营期 Ops Ready** | W7–8 | 审核后台、监控备份、压测、上线 |
| **增强期** | W9+ | 越南支付生产、PWA、礼物等 |

> **承诺改为：8 周可商业化上线**；前 2 周只打地基，不允许堆功能。

### ❌ 问题 2：多子域名 + Cookie 登录会炸（架构错误）

**原方案**：
- `www.example.com` 观众
- `creator.example.com` 创作者
- `admin.example.com` 管理

**问题**：
- Session Cookie 默认**不能跨子域名共享**
- 观众登录后进创作者后台要再登一次，或被迫配 `Domain=.example.com`（安全面变大、CSRF 更难防）
- 4 个独立 Next.js 应用 = 4 套部署、4 套 i18n、4 套代理，时间成本高

**修正（地基决策）**：

```
采用「单域名 + 路径分区」：

https://example.com/          → 观众端
https://example.com/creator/  → 创作者后台
https://example.com/admin/    → 管理后台
https://example.com/api/      → 代理到 NestJS

工程形态二选一（推荐 A）：
A) 1 个 Next.js App（route groups）+ 1 个 NestJS API   ← 推荐，省时间、登录简单
B) monorepo 多 app，但全部挂同一域名不同 path（仍共享 cookie）
```

**禁止**：MVP 阶段用多子域名拆端。SEO 落地页可后续再加子域。

### ❌ 问题 3：钱包只认 VND，却接微信/支付宝（账务模型错误）

**原方案**：内部统一 VND，同时接微信、支付宝、Stripe。

**问题**：
- 微信/支付宝结算币种是 **CNY**
- Stripe 多为 **USD / 当地币**
- 若强行「收到多少人民币就折算成越南盾入账」，必须明确：
  - 用哪天的汇率？
  - 汇率差谁承担？
  - 退款按哪天汇率？
- 不做这套规则，**账永远对不平**

**修正（地基决策）**：

```
账本本位：VND（BIGINT，无小数）——不变

充值入账规则：
1. 渠道回调带回「实付币种 + 实付金额 + 平台记账 VND」
2. 订单表同时存：
   - amount_vnd          （入钱包的越南盾）
   - pay_currency        （CNY / USD / VND）
   - pay_amount          （渠道实付）
   - fx_rate             （折算汇率，可空）
   - fx_source           （manual / openexchangerates / stripe）
3. 钱包只加减 amount_vnd，永远不存多币种余额

MVP 汇率策略（简单可跑）：
- VietQR / MoMo / ZaloPay：本来就是 VND，fx_rate = 1
- Stripe：用 Stripe 结算币 → 按配置表汇率折 VND（后台可改）
- 微信/支付宝：按后台配置的「固定汇率」折 VND（运营可调）
- 禁止：运行时调第三方汇率 API 且无落库（不可审计）
```

订单表必须加字段，否则地基不合格。

### ❌ 问题 4：HLS 只在「取播放地址」时鉴权（盗链漏洞）

**原方案**：`GET /episodes/:id/play` 校验解锁后返回 CDN 的 m3u8 URL。

**问题**：
- URL 一旦泄露，任何人都能看/转发
- 付费墙形同虚设

**修正（地基决策）**：

```
播放链路必须：

1. /play 校验解锁 → 签发「短时签名 token」（5–15 分钟）
2. m3u8 / ts 请求必须带 token（CloudFront signed URL 或自建鉴权网关）
3. token 绑定：userId + episodeId + 过期时间
4. 禁止返回永久公开的 HLS 地址
```

MVP 可用：CloudFront/阿里云 **带签名的 URL**；不要等「后期再加密」。

### ❌ 问题 5：支付「按 IP 自动选渠道」当主逻辑（产品错误）

**原方案**：越南 IP → MoMo；中国 IP → 微信。

**问题**：
- VPN、出差、华人在越南、越南人用中国手机号 → 全错
- 用户应**自己选**支付方式；IP 只做「默认排序建议」

**修正**：

```
展示规则：
1. 用户手动选择支付方式（主）
2. IP / locale 只影响「默认排序」（辅）
3. 所有已启用渠道都可选手动展示（后台开关）
```

---

### ❌ 问题 6：Webhook 无幂等 + 无对账（钱会丢/会多）

**原方案**：webhook 到了就改订单、加钱包。

**问题**：
- 渠道会**重复推送** webhook → 可能加款两次
- 网络超时重试 → 可能重复解锁
- 没有日对账 → 账实不符发现不了

**修正（地基必做，哪怕 UI 简陋）**：

```
1. orders.order_no 唯一 + webhook 用 order_no 幂等更新
2. 钱包流水加 unique(order_id, type) 防重复入账
3. 解锁表已有 unique(user_id, episode_id) —— 保持
4. 所有写钱操作：Serializable 事务 或 SELECT FOR UPDATE
5. wallets 加 version 字段做乐观锁（推荐）
6. 每日对账 Job：拉渠道账单 vs 本地 PAID 订单，差量告警
```

**没有幂等和对账骨架 = 不能上线收真钱。**

---

### ❌ 问题 7：WatchHistory / 收藏等细节会脏数据

**原方案**：`WatchHistory` 每次进度都 insert。

**问题**：表会爆炸，历史列表重复。

**修正**：

```
WatchHistory：@@unique([userId, episodeId])，进度用 upsert
Favorite：已有 unique —— 保持
Progress 上报：30s 节流 + upsert
```

## 二、修正后的正确地基决策（冻结）

以下决策 **MVP 期间不允许再摇摆**：

| # | 决策 | 内容 |
|---|---|---|
| F1 | **域名模型** | 单域名路径分区：`/`、`/creator`、`/admin` |
| F2 | **前端形态** | 优先 1 个 Next.js + route groups；不要 4 子域 |
| F3 | **账本本位** | 钱包只记 VND；订单存多币种实付 + 汇率快照 |
| F4 | **支付抽象** | PaymentProvider 接口 Day1；渠道可插拔 |
| F5 | **支付接入顺序** | ①接口全预留 ②先通 1 个真收款（建议 VietQR 或 Stripe）+ 银行转账兜底 ③微信/支付宝接好可测 ④MoMo/ZaloPay 生产后置但接口不砍 |
| F6 | **播放安全** | HLS 短时签名 URL，禁止永久公开链 |
| F7 | **写钱安全** | 幂等键 + 事务 + 钱包 version + 日对账 Job |
| F8 | **双语** | Day1 next-intl；**越南语 vi（默认）+ 中文 zh**；文案/标题/SEO 全双语 |
| F9 | **分类 i18n** | 分类用 slug + i18n key，不要只存越南语字符串 |
| F10 | **时间线** | **8 周可商业化**；前 2 周只打地基 |
| F11 | **脚手架** | 官方工具链自建，不整仓 fork 冷门模板 |
| F12 | **配置中心** | `system_settings` 表：默认免费集数、最低提现、汇率、分成比例 |

## 三、支付接入「正确姿势」（修正）

### 3.1 分层

```
┌─────────────────────────────────────┐
│ 业务层：充值 / 解锁 / 退款           │  ← 只认 VND + order_no
├─────────────────────────────────────┤
│ 支付抽象：PaymentProvider           │  ← Day1 冻结接口
├─────────────────────────────────────┤
│ 渠道适配：Stripe/微信/支付宝/MoMo…  │  ← 可先后接通
├─────────────────────────────────────┤
│ 对账层：日对账 Job + 人工补单        │  ← 上线收钱前必须有
└─────────────────────────────────────┘
```

### 3.2 MVP 接通优先级（务实）

| 优先级 | 渠道 | 原因 |
|---|---|---|
| P0 | **支付接口骨架 + 幂等 webhook** | 地基 |
| P0 | **银行转账（手动确认）** | 一定能收款，不依赖第三方审核 |
| P0 | **VietQR（或聚合：PayOS/Casso）** | 越南本地真实可用，比 Stripe 更贴市场 |
| P1 | **Stripe** | 海外卡；注意越南卡支持有限，不能当唯一主力 |
| P1 | **微信 + 支付宝** | 国内测账、团队使用；接口 Day1 预留并尽量接通 sandbox |
| P2 | **MoMo / ZaloPay 生产** | 商户审核慢，接口与 sandbox 先做好 |

> **纠正 v6 的错误**：不要把「Stripe + 微信 + 支付宝三个生产全通」当成 Week2 硬指标。  
> **正确硬指标**：抽象层完备 + 至少 **1 条自动收款链路** + **1 条手动兜底** + **对账能跑**。

## 五、安全地基清单（上线收钱前必须）

| 项 | 要求 |
|---|---|
| HTTPS 全站 | 必须 |
| Cookie | httpOnly + Secure + SameSite=Lax；单域名 |
| HLS | 短时签名 URL |
| 上传 | 鉴权后才发 TUS；文件类型/大小白名单 |
| 管理后台 | 独立角色 `admin`，二次校验；提现双人复核（可后期） |
| 密钥 | 只放服务端 env，不进前端 bundle |
| 限流 | OTP 发送限流、登录限流、支付创建限流 |
| CCCD | 加密存储或对象存储私有桶 + 访问审计 |
| 日志 | 禁止打印完整卡号/OTP/证件号 |

## 六、性能地基（务实版，别一上来读写分离）

**错误**：MVP 就上主从、多实例、1 万并发承诺。

**正确分层**：

| 阶段 | 性能目标 | 做法 |
|---|---|---|
| 地基期 | 单机稳定 | 索引齐全、连接池、Redis 缓存热点 |
| 上线期 | 千级同时在线 | CDN 扛视频、API 垂直扩 2 实例 |
| 增长期 | 万级 | 读写分离、转码独立机器 |

视频流量与 API 流量分开算：**CDN 扛片，应用服务器扛接口**。  
「1 万并发」应主要指 **CDN 侧播放连接**，不是 NestJS 单机扛 1 万 QPS。

## 七、修正后的 8 周路线（替换原 4 周）

### W1–2 地基期（不准堆业务花活）

- monorepo（官方脚手架）+ 单域名路径分区
- next-intl 双语全通
- Prisma schema（含幂等、version、多币种字段、settings）
- Better Auth 手机号 OTP（可 mock SMS）
- PaymentProvider 接口 + webhook 幂等框架 + 日对账骨架
- TUS + FFmpeg → HLS + **签名播放 URL**
- Docker Compose 一键起

**地基期验收**：没有「真用户充值」也可以，但**写钱路径的代码骨架与测试必须绿**。

### W3–4 闭环期（上半）

- 创作者：上传、定价、提交审核
- 观众：浏览、播放、登录
- 钱包 + **1 条自动支付** + 银行转账兜底
- 单集解锁事务

### W5–6 闭环期（下半）

- 70/30 分账 + T+7
- 提现申请 + 后台审核
- 微信/支付宝接通（sandbox/生产视资质）
- 越南渠道 sandbox 跑通

### W7–8 运营上线期

- 审核/Banner/基础看板
- 监控、备份、压测（目标：千级在线稳定）
- 域名 HTTPS、CDN
- 真实内容 + 真实小额交易 + 真实提现
