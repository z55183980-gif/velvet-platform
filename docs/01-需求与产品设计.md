## 〇、项目原则（核心约束）

### 原则 1：基础功能都要有

**基础功能清单上线**（详见 README；排期以 **8 周**为准，见 00 / 04）。

### 原则 2：双语从 Day 1 开始就有

**不是后期加，是 Day 1 就实现**：

- ✅ 越南语 (vi) 默认 + **中文 (zh)**
- ✅ 所有页面、所有按钮、所有提示、所有错误信息
- ✅ 短剧标题、简介支持双语（vi + zh）
- ✅ 顶部语言切换器，URL 路由前缀（`/zh/...`）
- ✅ 金额、日期、时区本地化
- ✅ 后续可扩展英语等（加 JSON 文件即可）

### 原则 3：支付多渠道预留接口

**业务逻辑只依赖 PaymentProvider 接口，渠道切换零侵入**：

| 渠道 | 状态 | MVP 必做？ |
|---|---|---|
| **Stripe（国际信用卡）** | MVP 必接 | ✅ 必做 |
| **微信支付** | MVP 必接 | ✅ 必做（团队测试用）|
| **支付宝** | MVP 必接 | ✅ 必做（团队测试用）|
| **银行转账（手动）** | MVP 必做 | ✅ 兜底 |
| **MoMo** | 接口预留 + sandbox | ⭐ 必做（接口） |
| **ZaloPay** | 接口预留 | ⭐ 必做（接口） |
| **VietQR** | 接口预留 | ⭐ 必做（接口） |

**实现要求**：
- 所有支付代码集中在 `packages/payments/`
- 业务代码（订单、解锁）只调接口，不直接调任何 SDK
- 新增渠道 = 加 1 个 `xxx.provider.ts` 文件

### 原则 4：基础运营要考虑

**人少开发 ≠ 运营糙**：

- 性能务实：千级同时在线稳定（CDN 扛视频、Redis 缓存、连接池；万级为增长期目标，见 00 §六）
- 数据库有索引、有备份
- 监控告警齐全
- 错误日志全收集

### 原则 5：不做花哨功能（后期补）

- ❌ 整剧打包（先单集）
- ❌ 打赏/礼物
- ❌ 工作室多成员
- ❌ 二级分销
- ❌ Zalo 登录（先手机号）
- ❌ 移动 PWA / App 上架
- ❌ 倍速、画中画

## 一、项目愿景

**Velvet**：越南领先的纯 Web 短剧内容平台，连接**官方自制 + 创作者分享 + 合作方授权**三类内容供给方。

### 1.1 商业模式

```
总流水 Vtotal (₫)
├── 创作者应得：Vcreator = Vtotal × revenue_share（默认 70%）
└── 平台抽成：Vplatform  = Vtotal - Vcreator（默认 30%）
```

## 六、支付渠道矩阵（MVP）

### 6.1 渠道接入策略

| 渠道 | 区域 | 接入方式 | MVP 必做 | 备注 |
|---|---|---|---|---|
| **Stripe** | 全球 | Checkout + Webhook | ✅ 必接 | 海外信用卡 |
| **微信支付** | CN | Native + Webhook | ✅ 必接 | 国内测试 |
| **支付宝** | CN | Web 支付 + Webhook | ✅ 必接 | 国内测试 |
| **银行转账** | GLOBAL | 手动对账 + 后台标记 | ✅ 必做 | 兜底方案 |
| **MoMo** | VN | App-to-App + IPN | ⭐ 接口预留 | 预留+sandbox |
| **ZaloPay** | VN | Redirect + Webhook | ⭐ 接口预留 | 预留 |
| **VietQR** | VN | 动态二维码 + Webhook | ⭐ 接口预留 | 预留 |

### 6.2 前端展示策略（修正：用户自选为主）

```typescript
// ❌ 错误：仅按 IP 强制渠道
// ✅ 正确：后台开关控制「启用渠道」；IP/locale 只影响默认排序；用户最终自选

function listPaymentMethods(userIp: string, locale: string, enabled: string[]) {
  const preferred = detectPreferredOrder(userIp, locale); // 仅排序建议
  return preferred.filter((m) => enabled.includes(m));
}
```

接入优先级见 [00 文档 §三](./00-地基复盘与修正.md)：先 **抽象+幂等+对账**，再 **银行转账兜底 + 至少 1 条自动收款（VietQR/聚合）**，微信/支付宝/Stripe 按资质接通，MoMo/ZaloPay 生产可后置但接口不砍。

### 6.3 后端抽象

```typescript
// packages/payments/src/index.ts
export const paymentProviders = {
  stripe: new StripeProvider(),
  wechat: new WechatPayProvider(),
  alipay: new AlipayProvider(),
  momo: new MomoProvider(),         // 预留
  zalopay: new ZaloPayProvider(),   // 预留
  vietqr: new VietQRProvider(),     // 预留
  bank_transfer: new ManualBankTransferProvider(),
};

export function getProvider(method: string): PaymentProvider {
  return paymentProviders[method] || paymentProviders.bank_transfer;
}
```

## 七、关键业务规则

### 7.1 免费试看

- 默认前 **3 集免费**（创作者可在后台调整 1-10 集）
- 整剧免费：创作者可设置全部免费

### 7.2 收益与提现

- 默认分润 **70%（创作者）/ 30%（平台）**
- **T+7** 自动解冻
- 最低提现 **100,000 ₫**
- MVP 阶段：手动银行打款（管理员操作）

### 7.3 退款

- 已解锁剧集：不退
- 充值未消费：原路退款（T+3）
- 系统故障：人工审核 24h 内退款

## 八、用户故事（MVP 必跑通）

### US-1：观众完整闭环

```
1. 打开 example.com（默认越南语）
2. 看到首页推荐（无需登录）
3. 点击感兴趣的剧 → 详情页
4. 观看前 3 集免费
5. 第 4 集 🔒 + 1,000 ₫
6. 弹窗引导登录（手机号 OTP）
7. 登录后充值：选择支付渠道
   - 越南用户 → 看到 MoMo/ZaloPay/VietQR/Stripe
   - 中国用户 → 看到 微信/支付宝/Stripe
8. 充值 50,000 ₫ → 解锁第 4 集
9. 继续观看，记住进度
10. 个人中心看到钱包、订单、历史
```

### US-2：创作者完整闭环

```
1. 访问 `example.com/creator`
2. 注册 + CCCD 实名 + 绑卡
3. 创建短剧（填 en/zh 标题）
4. 上传视频（断点续传）
5. 后台转码 HLS 完成
6. 设定价格（第 1-3 集免费，第 4+ 集 1,000 ₫）
7. 提交审核
8. 管理后台（`example.com/admin`）通过 → 上线
9. 后台看到播放/解锁数据
10. 累计 100k ₫ 后申请提现
11. 管理员审核通过 → 银行打款
```

### US-3：双语切换（越南语 ↔ 中文）

```
1. 用户访问 example.com → 默认越南语
2. 点击右上角「中文」→ 整个网站切中文
3. URL 变为 example.com/zh/...
4. 下次访问记住语言偏好（locale=zh）
```

## 九、非功能性需求

| 类别 | 要求 |
|---|---|
| **性能** | 首屏 < 1s，视频起播 < 1s |
| **并发** | 千级同时在线稳定（上线目标）；万级为增长期目标（指 CDN 侧播放连接，非 NestJS QPS，见 00 §六）|
| **可用性** | 99.5%（MVP 阶段）|
| **安全** | HTTPS、HLS 签名 URL、CCCD 加密 |
| **备份** | 每日自动备份，保留 30 天 |
| **SEO** | 短剧名称被 Google Vietnam 收录 |
| **国际化** | vi + zh，扩展性预留 |
