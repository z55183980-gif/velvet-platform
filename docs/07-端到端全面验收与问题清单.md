## 二、严重问题（必须修）

### P0-1：Webhook 任意刷单
**位置**：`services/api/src/payments/payments.controller.ts:73` `@Post('webhooks/:provider')`

`/api/v1/webhooks/<provider>`（非 alipay）**完全无签名、无鉴权**，任何人 POST `{orderNo, status}` 都可把该订单标为 PAID → 钱包自动到账。

**复现**：
```bash
# 1. 任意用户先下一笔充值单
curl -X POST .../api/v1/orders/topup -d '{"currency":"VND","amountFiat":200000,"paymentMethod":"STRIPE"}'
# → 得到 orderNo = TPxxxxx

# 2. 任何人不带任何 token，调 webhook：
curl -X POST http://localhost:4000/api/v1/webhooks/stripe \
  -H 'content-type: application/json' \
  -d '{"orderNo":"TPxxxxx","status":"paid"}'
# → 200 OK，订单变 PAID，用户钱包凭空 +200000 积分
```

**修复**：
1. 非 alipay 的 webhook 必须验签（Stripe signature / MoMo checksum 等）
2. 至少加 IP 白名单 + 商户密钥
3. 必须校验 `paymentMethod` 与 `provider` 一致
4. 接受回调的渠道限定在支付网关出口 IP

---

### P0-2：用户自助退款充值单
**位置**：`services/api/src/wallet/wallet.controller.ts:45` `POST orders/:orderNo/refund`

**复现**：观众充值 50000 VND → 模拟支付成功 → 立即调 `POST /api/v1/orders/<topup_orderNo>/refund` → 直接退积分。

**危害**：可反复「充值→退款」刷积分，对账也会出现负 spent。

**修复**：
- 充值单（orderType=TOPUP）退款必须经管理员审核，或禁止用户自助退
- 退款接口必须校验 orderType = EPISODE_UNLOCK

---

### P0-3：剧集价格为负可入库
**位置**：`services/api/src/creator/creator.controller.ts:54` `createEpisode`

```bash
curl -X POST .../api/v1/creator/dramas/23/episodes \
  -d '{"episodeNumber":2,"isFree":false,"priceVnd":-1000}'
# → 200 OK，DB 里存 priceVnd=-1000, priceCredits=-1000
```

观众解锁此剧集 = "扣 -1000 积分" = 凭空送积分。

**修复**：episode DTO 必须 `@Min(0)` 校验 priceVnd/priceCredits/isFree 组合。

---

### P0-4：KYC 驳回端点缺失
**位置**：`services/api/src/admin/admin.controller.ts` —— 没有 `POST creators/:id/kyc/reject`

管理员只能"通过"，不能"驳回"。导致问题 KYC 永远卡在 PENDING。

**修复**：补 `@Post('creators/:id/kyc/reject')` + service `rejectKyc(creatorId, reason)`，逻辑类似 withdraw reject（含 reason 必填）。

---

### P0-5：mark-paid 把已 REFUNDED 订单重置为 PAID
**位置**：`services/api/src/admin/admin.service.ts:178` `markPaid`

用户先充值→refund（绕过 P0-2）→ 管理员 mark-paid → 订单又变 PAID，refundAt 字段还在但 status 不一致。会造成对账错乱 + 二次到账。

**修复**：
1. mark-paid 前校验 `paymentStatus != 'REFUNDED'`
2. 或者校验 idempotencyKey 与外渠道返回的一致性

## 三、高优先级问题（建议修）

### P1-1：Prisma 原始错误直接暴露给前端
**位置**：所有 service 层（creator/admin/dramas）

如 `creator.service.ts:149` 创剧集缺 titleEn 时返回：
```
Invalid `this.prisma.drama.create()` invocation...
Argument `titleEn` is missing.
```

可被用于探测数据库结构。应包成 `BizException(BizCode.BAD_REQUEST, '缺少必要字段 titleEn')`。

**修复**：所有 service 加 try-catch，捕获 Prisma `PrismaClientKnown*Error`，按 P-codes 翻译成 BizException。

---

### P1-2：KYC 提交无任何校验
**位置**：`services/api/src/creator/creator.service.ts:submitKyc`

```bash
curl -X POST .../api/v1/creator/kyc/submit -d '{}'  # 200 OK
curl -X POST .../api/v1/creator/kyc/submit \
  -d '{"cccdFrontUrl":"javascript:alert(1)"}'  # 200 OK
```

**修复**：
- cccdNumber: 9 或 12 位数字校验
- cccdFrontUrl/BackUrl: 必须 `^/api/v1/media/` 或 https://
- faceVerified: 强制 true
- bankAccount: 必填
- taxCode: 必填

---

### P1-3：管理员汇率可改 0 / 负数
**位置**：`services/api/src/admin/admin.service.ts` `upsertRate`

```bash
curl -X POST .../api/v1/admin/exchange-rates \
  -d '{"currency":"CNY","buyRate":3400,"sellRate":0}'  # → 1 积分换 0 法币
curl -X POST .../api/v1/admin/exchange-rates \
  -d '{"currency":"CNY","buyRate":-100,"sellRate":200}'  # → 充值倒贴
```

**修复**：
- `buyRate > 0`, `sellRate > 0`
- 至少 `sellRate >= buyRate * 0.95`（留出点差）

---

### P1-4：观众进度上报无边界
**位置**：`services/api/src/episodes/episodes.controller.ts:32` `progress`

```bash
curl -X POST .../api/v1/episodes/57/progress -d '{"progressSec":-5,"durationSec":105}'  # 200
curl -X POST .../api/v1/episodes/57/progress -d '{"progressSec":9999,"durationSec":105}'  # 200
```

**修复**：service 内 `if (progressSec < 0 || progressSec > durationSec) throw ...`

---

### P1-5：剧集提交审核把已 LIVE 强制回 PENDING
**位置**：`services/api/src/creator/creator.service.ts:submitReview`

```bash
curl -X POST .../api/v1/creator/dramas/18/submit-review  # 18 是 LIVE
# → 200 OK，状态被改成 PENDING_REVIEW
```

创作者可恶意把已上线剧集踢下线（影响已付费用户）。

**修复**：service 校验 `if (drama.status !== 'DRAFT' && drama.status !== 'REJECTED') throw BizException(CONFLICT, '当前状态不允许提交')`

---

### P1-6：剧集空也可提交审核
**位置**：`services/api/src/creator/creator.service.ts:submitReview`

```bash
curl -X POST .../api/v1/creator/dramas/24/submit-review  # 0 集
# → 200 OK
```

**修复**：`if (await tx.episode.count({where:{dramaId}}) === 0) throw ...`

---

### P1-7：重复审核返回"成功"但状态不变
**位置**：`admin.service.ts:approveDrama` / `rejectDrama`

```bash
curl -X POST .../api/v1/admin/dramas/19/reject  # 19 已 REJECTED
# → 200 OK {status:"REJECTED"}
```

前端可能误以为新一次审核生效。建议返回 `409 CONFLICT` 或 `alreadyProcessed: true`。

---

### P1-8：AdminGuard 默认 HTTP 状态 400 而非 403
**位置**：`services/api/src/common/biz.exception.ts:11`

```ts
new BizException(BizCode.FORBIDDEN, 'Không có quyền quản trị')
```
BizException 构造默认 `httpStatus=400`，导致未带 admin token 时返回 400，监控/告警难识别。

**修复**：所有 guard 显式传 `HttpStatus.FORBIDDEN`。

---

### P1-9：详情接口 404 协议不一致
**位置**：`dramas.service.ts` `getDramaById`

不存在时返回：
```json
{ "code": 0, "message": "Không tìm thấy", "data": null }
```

其他 404 都返回 `{code:404, ...}`。前端需要按 `data == null` 特判，应统一为 `404`。

---

### P1-10：me/locale 端点缺失
**位置**：`users.controller.ts` 没有 `PATCH /users/me/locale`

前端 `i18n.tsx` 调用但后端没实现（详情见 v1 报告 P1-3）。**仍存在。**

## 四、中优先级问题

### P2-1：OTP 无次数限制
错码可无限试。建议 5 次错误锁 15 分钟。

### P2-2：OTP 给不存在的邮箱也发
可探测邮箱注册名单。建议先做存在性判断再发码。

### P2-3：phone OTP 字段名歧义
- send 端用 `phoneNumber`
- verify 端用 `phone`（DTO 提示）

**修复**：统一字段名。

### P2-4：上传 MIME 误判
`.mp4` 文件返回 `application/octet-stream`。可后端按扩展名兜底。

### P2-5：上传成功后 durationSec 未写
ffmpeg probe 没把时长写回 episodes 表。详见 `upload.service.ts` 异步队列。

### P2-6：drama18 hlsUrl 是 .mov 不是 .m3u8
种子数据里 drama20 的 hlsUrl 写成了 `.mov`，跟接口契约不符。需要排查 import 脚本。

### P2-7：drama17 episode 136 hlsUrl 是 "末世之约/末世之约1.mp4"
复用错的 path，transcodeStatus 还是 PENDING。

### P2-8：测试提现 method 字段不存
前端 `/creator/withdraws` 没传 method，后端也没存。bankInfo 仅做空对象。

### P2-9：episode-list 已解锁仍显示价格
文案层面：已解锁付费集下面还显示「10.000 积分」。按钮已修复为播放按钮。
