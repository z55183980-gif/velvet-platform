# Velvet 生产部署手册

> 用于将 `origin/main` 发布到生产环境。密码、数据库连接串和签名密钥只保存在服务器 `.env` 中，不得提交到仓库。

## 1. 生产环境

| 项目 | 值 |
|---|---|
| SSH | `starnexus-s4` |
| 代码目录 | `/www/wwwroot/velvet-platform` |
| 用户端 | https://velvetmovie.space |
| 管理端 | https://admin.velvetmovie.space |
| API | PM2 `velvet-api`，端口 `4100` |
| Worker | PM2 `velvet-worker`（BullMQ 转码；需 Redis） |
| Web | PM2 `velvet-web`，端口 `3100` |
| Admin | PM2 `velvet-admin`，端口 `3001` |
| PostgreSQL | Docker `velvet-postgres`，端口 `5432` |
| Redis | Docker `velvet-redis`，端口 `6379`（转码队列） |

## 2. 标准发布

### 2.1 推送代码

先在本地确认代码已推送到 `main`：

```bash
git push origin main
```

### 2.2 登录生产服务器

```bash
ssh -o BatchMode=yes starnexus-s4
```

### 2.3 同步代码（每次必做）

```bash
set -euo pipefail
cd /www/wwwroot/velvet-platform

# 记住发布前版本，便于判断本次变更
OLD_SHA=$(git rev-parse HEAD)
git fetch origin main
git reset --hard origin/main
NEW_SHA=$(git rev-parse HEAD)
git log -1 --oneline

# 查看本次更新了哪些文件
git diff --name-only "$OLD_SHA" "$NEW_SHA"
```

### 2.4 按变更执行特殊步骤

不要每次都执行依赖安装和数据库迁移。根据上一步的文件列表判断：

| 变更文件 | 需要执行 |
|---|---|
| `pnpm-lock.yaml`、`package.json`、`pnpm-workspace.yaml` 或子项目 `package.json` | `pnpm install --frozen-lockfile` |
| `services/api/prisma/migrations/**` | `npx prisma migrate deploy`（`pnpm --filter velvet-api build` 的 `prebuild` 会再跑 `prisma generate`） |
| `services/api/prisma/schema.prisma` | 同上；有新迁移则先 `migrate deploy` |
| 仅业务代码、样式或文案 | 跳过依赖安装；API 构建仍会经 `prebuild` 执行 `prisma generate` |

需要安装依赖时：

```bash
cd /www/wwwroot/velvet-platform
pnpm install --frozen-lockfile
```

需要迁移数据库时：**先完成新 API 构建**，再在短维护窗口内 `migrate deploy` → 立即 `pm2 restart`。  
旧 API 进程继续跑时执行破坏性迁移会导致读写错配；尽量把「迁移 + 重启」做成同一窗口，且仅在 CI（migrate deploy + schema drift 检查）通过后执行。

**财务 / 破坏性迁移额外门槛（P1）：**

1. CI 空库 migrate ≠ 生产形状证明。发布前按 `scripts/prod-snapshot-rehearsal.md` 在 **prod 快照 → staging** 上跑 `scripts/finance-migrate-rehearsal.sql` 前后 checksum。
2. Prefer **expand → deploy app → contract**（先加列/可空，再切读，最后删旧列）。不要依赖「应用启动失败自动回滚 DB」——**没有**该能力。
3. 迁移窗口前：`bash scripts/dr-backup-checklist.sh`（需 `DATABASE_URL` + `pg_dump`）→ **`bash scripts/pre-migrate-gate.sh`**（UTC + 双列钱包一致性；失败则中止）。
4. 保持 `FINANCE_OPS_FROZEN=1` 直至 `docs/12-财务单位与对账.md` 清单完成；冻结期 **TOPUP/VIP money-in 关闭**；解冻前跑 deferred 回填脚本。
5. 服务器 `.env` / `.env.*`：**权限 `0600`**（`chmod 600`）；若曾出现世界可读备份（如 `0644`），**轮换** `CDN_SIGN_KEY` / JWT / Stripe / DB 等密钥后再重启（勿把密钥贴进工单/聊天）。

```bash
cd /www/wwwroot/velvet-platform/services/api
bash ../../scripts/pre-migrate-gate.sh
npx prisma migrate deploy
```

需要重新生成 Prisma Client 时：

```bash
cd /www/wwwroot/velvet-platform/services/api
npx prisma generate
```

### 2.5 构建和重启（每次必做）

**推荐顺序（降低非原子窗口）：**

1. `git pull` / 同步 `origin/main`（确认 CI 绿）
2. `pnpm install`（如有 lock 变更）
3. **先 build 全部产物**（旧进程仍服务旧 `dist`）
4. 若有新迁移：维护公告 → `prisma migrate deploy` → **立刻** PM2 restart
5. Smoke `https://velvetmovie.space/` 与关键 health

API 构建前必须已有与 `schema.prisma` 一致的 Prisma Client。`velvet-api` 的 `prebuild` / `pretypecheck` 会强制 `prisma generate`；干净环境或排查构建失败时也可显式执行。

```bash
cd /www/wwwroot/velvet-platform

pnpm --filter velvet-api prisma:generate
pnpm --filter velvet-api typecheck
pnpm --filter velvet-api build
pnpm --filter velvet-web build
pnpm --filter velvet-admin build

# 仅当本次含未部署迁移时，在 restart 前执行：
# cd services/api && npx prisma migrate deploy && cd ../..

pm2 restart velvet-api velvet-worker velvet-web velvet-admin
sleep 4
pm2 list
```

如果本次修改了服务器 `.env`，使用：

```bash
pm2 restart velvet-api velvet-worker velvet-web velvet-admin --update-env
```

### 2.5.1 转码 Worker / Redis（主流直传链路）

生产推荐路径：

1. 浏览器 Presign → PUT `velvet-uploads`
2. API `from-r2` 确认 → 临时落盘 `STORAGE_ROOT/uploads`
3. BullMQ 入队 → `velvet-worker` ffmpeg → HLS
4. 推送 `velvet-media` / CDN 后删除本机 `uploads/` 与 `hls/{jobId}/`

服务器 `.env`（`services/api`）：

```bash
REDIS_URL=redis://127.0.0.1:6379
TRANSCODE_INLINE=false
TRANSCODE_CONCURRENCY=1
```

首次启用 Redis / worker：

```bash
# Redis（示例）
docker run -d --name velvet-redis --restart unless-stopped -p 127.0.0.1:6379:6379 redis:7-alpine

# PM2 worker（在仓库根或 api 目录，cwd 指向 api 以便读 .env）
cd /www/wwwroot/velvet-platform/services/api
pm2 start dist/src/worker.js --name velvet-worker --update-env
pm2 save
```

生产环境启动强制要求 `REDIS_URL`（OTP / CAPTCHA / OAuth state / 队列共享存储）；缺省会 fail-fast。本地单进程开发可不设（回退内存 Map + 进程内队列）。配置 Redis 且 `TRANSCODE_INLINE=false` 时必须保证 `velvet-worker` online。

### 2.5.2 Google 登录（可选）

用户端登录弹窗支持 Google OAuth（弹窗 `postMessage` 回写会话）。在 `services/api/.env` 配置：

```bash
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
# 须与 Google Cloud Console「已授权的重定向 URI」完全一致；优先走站点同源 /api 反代
GOOGLE_REDIRECT_URI=https://velvetmovie.space/api/v1/auth/google/callback
AUTH_WEB_ORIGIN=https://velvetmovie.space
WEB_BASE_URL=https://velvetmovie.space
```

Google Cloud Console（OAuth 客户端类型：Web）：

- Authorized JavaScript origins：`https://velvetmovie.space`（及 `www` 如有）
- Authorized redirect URIs：与 `GOOGLE_REDIRECT_URI` 相同

改完 `.env` 后：`pm2 restart velvet-api --update-env`。可用 `GET /api/v1/auth/channels` 确认 `google.enabled === true`。

## 3. 数据库变更

只有本次发布包含 Prisma schema 或 migration 变更时，才执行本节命令。有新 migration 时执行：

```bash
cd /www/wwwroot/velvet-platform/services/api
npx prisma migrate deploy
npx prisma generate
```

如果出现 `P3005`，说明生产库可能没有完整的 Prisma 迁移历史。**禁止在生产用 `prisma db push` 强行对齐**。应：

1. 备份数据库；
2. 用 `prisma migrate resolve` / 补齐 ` _prisma_migrations` 历史，或在 staging 验证后手工执行审过的 SQL；
3. 再跑 `npx prisma migrate deploy`。

> 不要在生产环境执行 `prisma migrate reset` 或 `prisma db push`。删列、改类型等破坏性变更必须先备份数据库，并审核迁移 SQL。

## 4. 发布验证

```bash
# API 健康 / 就绪（就绪失败必须 503：DB、Redis、队列、worker heartbeat）
curl -fsS https://velvetmovie.space/api/health
curl -fsS https://velvetmovie.space/api/health/ready
# ready JSON 中 worker 应为 ok（TRANSCODE_INLINE=false 时依赖 velvet-worker 心跳）

# 网站和 API
curl -fsS -o /dev/null -w "web=%{http_code}\n" https://velvetmovie.space/
curl -fsS -o /dev/null -w "admin=%{http_code}\n" https://admin.velvetmovie.space/login
curl -fsS "https://velvetmovie.space/api/v1/dramas?pageSize=1"

# 进程和端口
pm2 list | grep velvet
ss -lntp | grep -E ':(3100|3001|4100|5432|6379)\b'
```

Web 和 Admin 应返回 `200`，API 应返回 JSON，`velvet-api` / `velvet-web` / `velvet-admin` 应为 `online`。启用 Redis 转码时 `velvet-worker` 与 `6379` 亦应可用；`/api/health/ready` 在 worker 心跳缺失/过期时不得为 200。


| 现象 | 检查 |
|---|---|
| 502 / 页面空白 | PM2 进程状态和日志 |

## 6. 代码回滚与迁移失败处置

将 `<good_sha>` 替换为已知正常的 commit：

```bash
cd /www/wwwroot/velvet-platform
git log -5 --oneline
git reset --hard <good_sha>
pnpm install --frozen-lockfile
pnpm --filter velvet-api build
pnpm --filter velvet-web build
pnpm --filter velvet-admin build
pm2 restart velvet-api velvet-worker velvet-web velvet-admin
curl -fsS https://velvetmovie.space/api/health/ready
```

> 代码回滚不会自动回滚数据库。数据库变更需要单独的备份或回滚 SQL。  
> **禁止**在未准备好 DB 回滚方案时，对含破坏性迁移的版本做「只回代码不回库」。

**迁移后应用起不来时：**

1. 不要再次 `migrate deploy` 碰运气；保留发布前 `pg_dump`。
2. 若迁移仅为 additive（新列/新表）：可先回滚代码到旧 SHA，旧代码应忽略新列。
3. 若迁移含 DROP/改类型：从 dump restore 到临时库验证后，再决定 restore prod 或手写 reverse SQL；**无自动 DB rollback**。
4. 财务相关：保持 `FINANCE_OPS_FROZEN=1`，对照 `scripts/finance-migrate-rehearsal.sql` checksum。

蓝绿/双槽尚未落地；当前为 **同机 in-place build + 短窗 migrate + restart**。残余风险：migrate 与旧进程重叠窗口、无流量切换槽。

## 7. GitHub 分支保护（需仓库 admin 手工配置）

代码无法代设。目标设置（Settings → Rules → Rulesets，或 Branches → Branch protection → `main`）：

| 设置 | 值 |
|------|-----|
| Target | `main` |
| Restrict deletions | on |
| Restrict force pushes | on |
| Require a pull request before merging | on（若仍直推 main：至少强制 status checks） |
| Required status checks | `API / build`，`Web + Admin / typecheck-build`，`CDN Worker / typecheck`（worker 路径变更时） |
| Require branches to be up to date | on |
| Do not allow bypassing the above settings | on（至少对非 admin） |
| Require conversation resolution | optional |
| Require linear history | optional |
| Restrict who can push | 仅 release 角色 / 禁止个人 PAT 直推（推荐） |

核对：

```bash
gh api repos/{owner}/{repo}/rulesets --jq '.[].name'
gh api repos/{owner}/{repo}/branches/main/protection || true
```

agent 无 admin 时只提供本清单；**当前 main 无保护 = 人为风险，须 ops 配置**。

## 8. 备份与 DR 演练清单

可执行脚本：`scripts/dr-backup-checklist.sh`（有 `DATABASE_URL` 时真实 `pg_dump` + TOC 校验；缺凭证 / 无 `pg_dump` **fail-closed**）。  
预迁移门禁：`scripts/pre-migrate-gate.sh`。  
财务快照演练：`scripts/prod-snapshot-rehearsal.md` + `scripts/finance-migrate-rehearsal.sql`。

### 发布产物（最小可行，本机尚无蓝绿）

当前生产是 **同机 live worktree + PM2 in-place build**，不是不可变 artifact / 蓝绿：

| 现状 | 最小改进（推荐下一步） |
|------|------------------------|
| `git pull` 后在 `/www/wwwroot/…` 直接 build | 构建到 `releases/<sha>/`，`current` 符号链接切换 |
| PM2 `cwd` 指向 worktree | PM2 指向 `current`；回滚 = 切回上一 sha 链接 + restart |
| 无自动 DB rollback | 每次 migrate 前 `dr-backup-checklist.sh`；破坏性迁移准备 reverse SQL |
| CDN Worker 手工 `wrangler deploy` | CI `CDN Worker` workflow 已对 `workers/velvet-cdn/**` typecheck；deploy 仍人工 |

每次演练勾选：

- [ ] 服务器已安装 `postgresql-client`（`pg_dump` / `psql`）
- [ ] `DATABASE_URL=… bash scripts/dr-backup-checklist.sh` 成功且 dump size > 0
- [ ] `bash scripts/pre-migrate-gate.sh` 通过（UTC + 无双列冲突）
- [ ] 备份校验：restore 到 staging 能 `migrate status` / smoke API / `/api/health/ready`
- [ ] `psql … -f scripts/finance-migrate-rehearsal.sql` 前后 checksum 已存档
- [ ] `STORAGE_ROOT` / R2 媒体抽样可恢复
- [ ] 回滚演练：选一含迁移的 commit，验证「代码回滚 + DB 前滚/回滚 SQL」剧本
- [ ] `.env` 权限 `0600`；若曾 `0644` 备份泄露风险 → **密钥轮换**（勿打印密钥）
- [ ] Stripe webhook / `CDN_SIGN_KEY` / `YTDLP_SHA256` / `.env` 密钥不在 git
- [ ] 演练记录日期、耗时、负责人

生产 **禁止** `prisma db seed`，除非 `ALLOW_PRODUCTION_SEED=1` 且强 `ADMIN_BOOTSTRAP_PASSWORD`（见 `seed.ts`）。
