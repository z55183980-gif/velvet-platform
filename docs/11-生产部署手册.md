# Velvet 生产部署手册

> **目标**：操作者 / Agent **不必再向人追问**主机、路径、端口，即可按本文完成 `main` → 生产发布与冒烟验证。  
> **机密**：密码、JWT、`CDN_SIGN_KEY`、数据库连接串 **只存在服务器 `.env`**，永不写入本仓库。

### 本机端口（服务器内）

| 服务 | 监听 | 进程 / 说明 |
|---|---|---|
| PostgreSQL | `127.0.0.1:5432` | `velvet-postgres` |
| API | `*:4100` | PM2 `velvet-api` → `dist/src/main.js`（`.env` 中 `PORT=4100`） |
| Web | `*:3100` | PM2 `velvet-web` → `npm start -- -p 3100` |
| Admin | `*:3001` | PM2 `velvet-admin` → `npm start`（`package.json` 默认 3001） |

### Nginx 反代（不要改端口除非同步改 PM2）

| 域名 | 配置 | 上游 |
|---|---|---|
| `velvetmovie.space` | `/www/server/panel/vhost/nginx/extension/velvetmovie.space/proxy.conf` | `http://127.0.0.1:3100` |
| `admin.velvetmovie.space` | `/www/server/panel/vhost/nginx/extension/admin.velvetmovie.space/proxy.conf` | `http://127.0.0.1:3001` |

API **不对公网直接暴露**；由前端 Next `rewrites` 代理：

- Web / Admin：`API_PROXY_TARGET`（生产应指向 `http://127.0.0.1:4100`）
- 浏览器侧统一走 `https://velvetmovie.space/api/...` 或管理端同源 `/api/...`

### SSH 别名约定（操作机）

生产机已在常用运维机 `~/.ssh/config` 配置。若新机器需补：

```sshconfig
Host starnexus-s4 sn-s4
    HostName 149.104.11.117
    User root
    Port 22
    IdentityFile ~/.ssh/starnexus_ops_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
    ConnectTimeout 15
```

连通性自检（不交互）：

```bash
ssh -o BatchMode=yes starnexus-s4 'hostname; pm2 list | grep velvet'
```

## 2. 标准发布流程（代码已推到 `origin/main`）

在**有 SSH 密钥的操作机**执行（PowerShell 也可；推荐远程一段 bash）。

### 2.1 一键发布脚本（复制即用）

```bash
ssh -o BatchMode=yes starnexus-s4 'bash -s' <<'EOF'
set -euo pipefail
cd /www/wwwroot/velvet-platform

echo "==> sync main"
git fetch origin main
# 仅丢弃部署机本地生成物（如 next-env.d.ts），不碰未跟踪密钥文件
git checkout -- . || true
git reset --hard origin/main
git log -1 --oneline

echo "==> install"
pnpm install --frozen-lockfile

echo "==> schema"
cd services/api
# 生产库早期用 db push / 手工建表，可能没有 _prisma_migrations。
# 优先 migrate deploy；失败则对「仅新增列」的 SQL 做幂等补丁，或 prisma db push（勿丢数据）。
if ! npx prisma migrate deploy; then
  echo "WARN: migrate deploy failed — applying additive SQL if needed, or use db push carefully"
  npx prisma db push
fi
npx prisma generate
cd ../..

echo "==> build"
pnpm --filter velvet-api build
pnpm --filter velvet-web build
pnpm --filter velvet-admin build

echo "==> restart"
pm2 restart velvet-api velvet-web velvet-admin
sleep 4
pm2 list

echo "==> smoke"
curl -fsS -o /dev/null -w "web=%{http_code}\n" https://velvetmovie.space/
curl -fsS -o /dev/null -w "admin=%{http_code}\n" https://admin.velvetmovie.space/login
curl -fsS "https://velvetmovie.space/api/v1/dramas?pageSize=1" | head -c 200; echo
echo DONE
EOF
```

### 2.2 分步对照

1. **先本地 / CI 推送**：`git push origin main`（见根目录 `SYNC.md`）。
2. **SSH 同步**：`git fetch` + `reset --hard origin/main`（部署机不要堆本地未提交业务改动）。
3. **依赖**：根目录 `pnpm install --frozen-lockfile`。
4. **数据库**：见 §3。
5. **构建**：`velvet-api` → `velvet-web` → `velvet-admin`（admin 使用 `next build --webpack`）。
6. **重启**：`pm2 restart velvet-api velvet-web velvet-admin`（改了 `.env` 时加 `--update-env`）。
7. **冒烟**：§5。

### 2.3 Windows / PowerShell 注意

远程多行 bash 在 PowerShell 里易被解析破坏。优先：

- `ssh ... 'bash -s' < deploy.sh`，或  
- 把脚本 base64 传到服务器再 `bash`，或  
- 将脚本写入仓库后 `scp` / `git pull` 后在服务器执行。

## 3. 数据库迁移注意（生产现状）

- 库名用户等以 `services/api/.env` 的 `DATABASE_URL` 为准（**勿打印完整 URL 到聊天/日志**）。
- 容器：`docker exec -it velvet-postgres psql -U <user> -d velvet`。
- **历史上可能没有 `_prisma_migrations`**。此时 `prisma migrate deploy` 会报 `P3005`。处理策略：

| 策略 | 何时用 |
|---|---|
| **`prisma db push`** | 仅加列/加索引、确认无破坏性变更时（当前常用） |
| **手工 `ALTER ... IF NOT EXISTS`** | 已有对应 `prisma/migrations/*/migration.sql` 时最可控 |
| **baseline + migrate deploy** | 有空时补齐迁移历史，再走正规 migrate |

表名均为 **snake_case**（Prisma `@@map`），例如 `dramas`、`episodes`、`sessions`。

## 4. PM2 进程约定

| name | cwd | 启动 |
|---|---|---|
| `velvet-api` | `.../services/api` | `node dist/src/main.js` |
| `velvet-web` | `.../apps/web` | `npm start -- -p 3100` |
| `velvet-admin` | `.../apps/admin` | `npm start`（端口 3001） |

常用：

```bash
pm2 logs velvet-api --lines 100
pm2 restart velvet-api --update-env
pm2 save   # 改过启动参数后执行，保证开机恢复
```

**不要**在生产用 `nest start --watch` / `next dev`。

首次从零拉起（仅灾备参考，平时用 restart）：

```bash
cd /www/wwwroot/velvet-platform/services/api && pm2 start dist/src/main.js --name velvet-api
cd /www/wwwroot/velvet-platform/apps/web && pm2 start npm --name velvet-web -- start -- -p 3100
cd /www/wwwroot/velvet-platform/apps/admin && pm2 start npm --name velvet-admin -- start
pm2 save
```

1. 用户端首页 / 剧场「最热」

3. 播放需**登录**后才签发 `/api/v1/media` 或 CDN 签名 URL

## 6. 片源与「真实播放」测试提示

- 相对路径片源放在 `STORAGE_ROOT`（默认 `services/api/storage`）下，例如 `imports/.../hls/index.m3u8`。  
- `episodes.hlsUrl` 填相对路径 → 播放走签名 `/api/v1/media/...`。  
- 绝对 `https://` URL 也可写入 `hlsUrl`，但查询串会附加 mock CDN 签名参数，**第三方公网直链可能被带参干扰**；优先本机存储 + HLS。  
- 管理端文件夹导入：`POST /api/v1/admin/import/local`（需 Admin JWT）。  
- 服务器需有 `ffmpeg`（生产已装）。
- **公开链接导入（yt-dlp）**：无需 API Key。API 启动时若本机没有 `yt-dlp`，默认（`YTDLP_AUTO_INSTALL=true`）会下载官方二进制到 `$STORAGE_ROOT/bin`。也可在镜像中预装（见 `services/api/Dockerfile`）并设置 `YTDLP_BIN`。管理端「添加剧集 → 在线剧集 → 公开链接解析」。

## 7. 回滚

```bash
ssh -o BatchMode=yes starnexus-s4 'bash -s' <<'EOF'
set -euo pipefail
cd /www/wwwroot/velvet-platform
git fetch origin main
git log -5 --oneline
# 换成已知良好的 commit
git reset --hard <good_sha>
pnpm install --frozen-lockfile
pnpm --filter velvet-api build
pnpm --filter velvet-web build
pnpm --filter velvet-admin build
pm2 restart velvet-api velvet-web velvet-admin
EOF
```

数据库回滚需另备 SQL / 备份；`db push` **不会**自动 downgrade。

## 8. 故障速查

| 现象 | 排查 |
|---|---|
| 502 / 页面空白 | `pm2 list`；Nginx `proxy_pass` 端口是否仍为 3100/3001；`pm2 logs` |
| API 404 / 代理失败 | `API_PROXY_TARGET` 是否指向 `http://127.0.0.1:4100`；API 是否监听 4100 |
| 构建失败 `next build` | 本地先 `pnpm --filter velvet-web build`；TypeScript 不过勿强推 |
| `migrate deploy` P3005 | §3：改用 `db push` 或幂等 SQL，勿盲目 `migrate reset` |
| 片源 403/404 | 路径是否在 `STORAGE_ROOT` 下；签名 `sig`/`exp`；`CDN_SIGN_KEY` 是否与签发一致 |
| 无法 SSH | 核对别名 `starnexus-s4`、密钥权限、服务器防火墙 |

## 9. Agent / 运维约定

发布任务默认假设：

1. 代码目标分支是 **`origin/main`**。  
2. SSH 目标是 **`starnexus-s4`**，目录 **`/www/wwwroot/velvet-platform`**。  
3. **不**向用户索要 IP/路径/PM2 名，除非 `BatchMode` SSH 失败。  
4. **不**把 `.env`、数据库密码、签名密钥写进仓库或提交说明。  
5. 改生产配置只改服务器文件；示例仍维护 `*.env.example`。  
6. 大版本 Node / 换机 / 改监听端口后，**先改本文 §1**，再改环境。
