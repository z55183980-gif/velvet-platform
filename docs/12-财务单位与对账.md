# 财务单位模型与对账（USD 全局）

**决策：全局统一使用美元（USD）。**  
账本最小货币单位为 **USD cents（整数）**。Prisma 列名仍含 `Vnd`（历史遗留），语义一律按 USD cents 解释；**不要**再建一套并行 VND 结算路径。

## 单位分层

| 概念 | 单位 | 存放位置 |
|------|------|----------|
| 法币账本 | USD cents | `orders.amountVnd` / `creatorIncomeVnd` / `platformFeeVnd`，`creator_earnings.*Vnd`，`withdraw_requests.amountVnd` |
| 支付快照 | USD major + FX | `payCurrency`（应为 `USD`）、`payAmount`、`fxRate`、`fxSource` |
| 产品积分 | credits（非货币） | `amountCredits`、`wallets.balanceCredits`、剧集 `priceCredits` |

Credits → USD cents 仅允许在**写入边界**按显式汇率换算：

- 环境变量 `USD_CENTS_PER_CREDIT`，或
- 平台设置（后续）`usdCentsPerCredit`

未配置汇率时：**禁止**把裸 credits 写入 `*Vnd` 货币列并计入创作者可提现余额。

## 已知脏数据（勿盲目回填）

1. Seed/历史剧集：`priceCredits=10` 且 `priceVnd=10000`（曾按 VND 理解），与 TOPUP 的 USD cents 混用。
2. 钱包解锁/买断：曾把 **credits** 直接写入 `amountVnd` / `creatorIncomeVnd`（例如 70% of 10 → `7`，被报表当成 7「VND」或 7 cents）。
3. Stripe 充值：`amountVnd` 已是 USD cents（与上两类不可直接 SUM）。

**禁止**在无订单级证据时批量改写历史 `*Vnd`。回填必须按订单类型 + 支付凭证逐类处理。

## 代码冻结（P1-2）

默认 `FINANCE_OPS_FROZEN=1`（设 `0`/`false` 解除）：

- 停止：创作者分成入账（`creditCreator`）、T+7 pending→available、提现申请、提现打款审批
- **停止 money-in**：`FINANCE_OPS_FROZEN=1` 时 Stripe **充值 TOPUP** 与 **VIP 订阅** 一并拒绝（`finance.opsFrozen` / 503），避免只进不出、与冻结出金不对称
- 报表：dashboard / stats 带 `financeOpsFrozen` + `reportsTrustworthy=false`
- **冻结期 + 已配置汇率**：已有积分的解锁/买断可继续；订单仍写 `amountVnd`（USD cents），`creatorIncomeVnd=0`；拟分成写入 `meta.deferredCreatorIncomeUsdCents` + `meta.creatorAccrualSkipped=true`。T+7 仅处理 `creatorIncomeVnd>0`
- **缺汇率 fail-closed**：未配置 `USD_CENTS_PER_CREDIT` 时，**TOPUP + 解锁/买断** 均拒绝（VIP 不依赖该汇率，解冻后可下单）。禁止出现「能充值但不能花」的困住用户态
- **`payAmount`**：始终为 USD major（`amountUsdCents/100`），禁止把 cents 原样写入 `payAmount`

### 解冻顺序（强制）

1. 完成下方人工对账清单  
2. 配置 `USD_CENTS_PER_CREDIT`  
3. **先 DRY_RUN 回填** deferred 创作者收入：  
   `DRY_RUN=1 pnpm --filter velvet-api exec ts-node --compiler-options "{\"module\":\"CommonJS\"}" ../../scripts/backfill-deferred-creator-income.ts`  
4. `FINANCE_OPS_FROZEN=0` 后 `DRY_RUN=0` 正式回填  
5. 再开放 settle / 提现 / money-in

## 人工对账清单（ops）

1. **盘点**：按 `orderType` + `paymentMethod` + `payCurrency` 分组，抽样核对 `amountCredits` vs `amountVnd` vs Stripe `payAmount*100`。
2. **TOPUP**：以 Stripe/支付渠道金额为准，确认 `amountVnd == USD cents`；修正异常行。
3. **EPISODE_UNLOCK / DRAMA_BUYOUT（WALLET）**：用订单当时套餐隐含汇率或统一宣布的 `USD_CENTS_PER_CREDIT` 重算 `amountVnd` / share 字段；无法证明汇率的订单标记 `meta.ledgerDirty=true` 并排除出结算。
4. **CreatorEarning**：由已校验订单重算 `pending/available/withdrawn`（勿直接缩放现有余额）。
5. **提现工单**：冻结期间 pending 提现人工审核；单位不明的拒绝并退回 available（在余额重算之后）。
6. **报表**：重算后改文案/字段别名为 USD；再设 `FINANCE_OPS_FROZEN=0`。
7. **后续迁移（可选）**：additive rename/新列 `amountUsdCents` 等——仅 additive，不改历史 migration SQL。

## 与 P1-4

买断结算与 VIP/免费永久解锁修复时，创作者 pending / T+7 **同一 USD cents 模型**；买断订单纳入 settle 查询时不得按 credits 入账。
